@defer (on interaction) { } @placeholder (minimum 400ms) {
Кликните сюда

Чанк с компонентом ещё не загружен

} @loading (after 100ms; minimum 500ms) {
Загружаем чанк и данные…
} @error {
Не удалось загрузить блок.
}

minimum у @placeholder и after у @loading убирают мерцание, когда чанк приходит слишком быстро. Важно: в режиме ng serve с включённым HMR Angular грузит зависимости @defer-блоков заранее (предупреждение NG0751 в консоли) — чтобы увидеть настоящую ленивую загрузку, запустите ng serve --no-hmr или соберите проект командой ng build.

Прокрутите ниже — там ждёт блок с триггером on viewport
@defer (on viewport; prefetch on idle) { } @placeholder {
Диаграмма появится при прокрутке
} @loading {
Строим диаграмму…
}

Здесь два независимых триггера: prefetch on idle скачивает чанк заранее, в простое браузера, а on viewport только отрисовывает его.

Показать вторую диаграмму @defer (when showChart()) { } @placeholder {
Переключатель выключен — блок не загружен
}

Важная деталь: @defer — это не @if. Загруженный блок остаётся в DOM, даже если условие снова станет ложным.

Триггер по умолчанию — on idle: если условие не указано, блок загрузится в первый простой браузера.
Инкрементальная гидратация появилась в Angular 19 и решает главную проблему SSR: раньше вся страница «оживала» целиком и сразу, скачивая весь JavaScript приложения. Теперь блок приходит готовым HTML, а его JavaScript загружается по триггеру.
